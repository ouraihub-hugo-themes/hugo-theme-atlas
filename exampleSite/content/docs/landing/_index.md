Landing 页是一个 layout，不是阅读外壳。front matter 里写 `layout: landing`，
section 从 `sections:` 数组来：

```yaml
---
title: 首页
layout: landing
sections:
  - type: hero
    headline: 标题
    tagline: 一段说明
    actions:
      - text: 开始
        href: /docs/
        style: primary
  - type: cards
    tone: muted
    title: 一组卡片
    items:
      - title: 安装
        href: /docs/
        icon: rocket
        body: 三条命令装完。
---
```

数组而不是 map：顺序是你要控制的东西，而 Go 模板遍历 map 按键排序 —— 那意味着
你得把 section 命名成 `01-hero`、`02-cards` 才能排出想要的次序。

[看渲染结果](/landing/)。

## 公共键

每个 section 都认这几个：

| 键 | 作用 |
| --- | --- |
| `type` | 必需，决定用哪个模板 |
| `id` | 容器 id，便于导航锚点；默认 `<type>-<序号>` |
| `tone` | `plain`（默认）、`muted`、`accent` |
| `title` | 节标题，渲染成 `h2` |
| `subtitle` | 标题下的说明 |
| `eyebrow` | 标题上方那行小字 |

`tone` 是成套取值而不是让你填十六进制：每档的前景色跟着背景配好，自己填颜色
容易做出对比度不足的组合。

**`title` 与 `subtitle` 渲染 Markdown，`eyebrow` 不渲染。** 前两个是叙述，在
标题里写 `code` 或强调是常事；`eyebrow` 是标签，`*` 在里面应该显示成星号。
这个区分在每个 section 的字段上都成立：叙述字段渲染，标签字段不渲染。

拼错的键会 warn。`titel` 写成这样时 Hugo 不报错，那个键只是静默不存在 ——
页面上少一行字而构建是绿的，所以主题必须替你报出来。

## hero

一屏的标题、说明、按钮，可选配图。

| 键 | 作用 |
| --- | --- |
| `headline` | 标题，渲染成 `h1` |
| `tagline` | 标题下的说明 |
| `image` | 配图，走和正文图片同一套三层解析 |
| `actions` | 按钮组 |

标题用 `headline` 而不复用公共的 `title`：公共 `title` 出 `h2`，而 hero 的标题
就是这一页的 `h1`。两个键名分开比同一个键在不同 section 里出不同层级更少意外。

配图的 `alt` 恒为空 —— hero 图承载的信息在标题与说明里已经说过了，给它一段重复
的 alt 只是让读屏软件念两遍。真正承载信息的图放正文里用图片语法，那里 alt 必需。

图是页面资源时会自动带上 `width`/`height`。远程图拿不到固有尺寸，那时不输出
这两个属性 —— 但代价是图载入前占 0 高，载入后把下面的内容顶下去。能放本地就
放本地。

## cards

卡片网格。每项：

| 键 | 作用 |
| --- | --- |
| `title` | 必需 |
| `body` | 描述，渲染 Markdown |
| `href` | 有它则整卡可点 |
| `icon` | 一个图标名 |
| `badge` | 标题旁的小标签，纯文本 |
| `image` / `image_alt` | 配图 |

卡片和 `card` shortcode 是同一份标记，所以样式和行为一致。列数不给参数：网格按
可用宽度 auto-fit，给一个 `columns: 3` 只会让你在窄屏上手动改回来。

一项写错只丢那一项 —— 六张卡里一处笔误不该把整节打空。

## metrics

几个大数字加各自的说明。每项：

| 键 | 作用 |
| --- | --- |
| `value` | 必需，那个数字 |
| `label` | 必需，它在量什么 |
| `note` | 补充说明 |

三个字段都是纯文本：数字与它的标签是数据而不是叙述，渲染 Markdown 只会让
`1.5*` 这样的值变成斜体。

**输出是 `<dl>` 而不是一排 `<div>`。** 每项是"值 + 它是什么"的配对，读屏软件
会把两者关联起来播报；用 `div` 的话读者听到的是两段互不相干的文字。

只有 `value` 没有 `label` 的项会被丢掉：一个孤零零的 `99.9%` 读者不知道它在量
什么，而显示出来看起来像渲染成功了。

## steps

编号步骤。每项：

| 键 | 作用 |
| --- | --- |
| `title` | 必需，这一步叫什么 |
| `body` | 说明，渲染 Markdown |

输出 `<ol class="steps">` —— 与你在 Markdown 里给有序列表标 `{.steps}` 得到的
是同一份标记，所以这一节没有自己的样式。编号来自列表本身，读屏软件报的是
"列表，N 项"。

不用 `<div>` 加 CSS 计数器自己画序号：那样看起来一样，但读屏软件听不出这是几步
里的第几步，而"这是一个流程"正是这一节要传达的东西。

## principles

几条主张，各带一段解释。每项：

| 键 | 作用 |
| --- | --- |
| `title` | 必需，那条主张 |
| `body` | 必需，为什么 |
| `icon` | 一个图标名 |

和 `cards` 的区别不是样式而是语义：`cards` 是一组入口（多数带链接，整卡可点），
`principles` 是一组陈述。字段也不同 —— 这里没有 `href`、`badge`、`image`。

`body` 必需：只有一句主张没有解释的话，这一节等于把标题重复了一遍。

## timeline

按时间排的条目。每项：

| 键 | 作用 |
| --- | --- |
| `date` | 必需，纯文本 |
| `title` | 必需 |
| `body` | 说明，渲染 Markdown |
| `status` | `done`（默认）、`current`、`planned` |

输出 `<ol>` —— 时间线是有序的，而这个顺序就是它要表达的东西。

`date` 只在能被机器读懂时带 `datetime` 属性：`2026-01-15`、`2026-06`、`2026`
三种形状都认，其余（"2027 年上半年"、"第二季度"）照原样显示但不带属性。塞一个
瞎猜的值比不给更糟 —— 机器会当真。

`status` 只改时间线上那个圆点，不调文字颜色：把 `planned` 的说明调淡会让它比
周围难读，而"这是计划中的"这个信息由旁边的日期承担。

## faq

问答折叠。每项：

| 键 | 作用 |
| --- | --- |
| `question` | 必需，纯文本 |
| `answer` | 必需，渲染 Markdown |

用原生 `<details>`/`<summary>`，零 JS：键盘操作、`aria-expanded` 等价语义、页内
搜索能找到收起的内容，这些浏览器都有。

`question` 不渲染 Markdown：它进 `<summary>`，而那里是控件的可访问名，标记会
打断读屏软件的连读。

**不做成手风琴。** `<details name="...">` 能让同组里只能展开一个，但那意味着你
想对比两个答案时前一个被强制收起。FAQ 是查阅而不是导航。

打印时所有答案自动摊开 —— 纸上没有"展开"这个动作。

## pricing

套餐卡片。每项：

| 键 | 作用 |
| --- | --- |
| `name` | 必需 |
| `price` | 必需，纯文本（"免费"、"联系我们"都行，不必是数字） |
| `period` | 计费周期，"每月"一类 |
| `description` | 一句话 |
| `features` | 纯文本数组 |
| `actions` | 见下面 |
| `featured` | 布尔，突出这一张 |
| `badge` | 突出那张上的一句话，"最常选"一类 |

价格与周期分成两个键，不要写成 `"¥299/月"`：货币位置、斜杠、周期词序各语言
不同，而分开之后价格能单独放大，周期不跟着放大。

`badge` 不自动生成 —— 那句话是营销文案，不是主题该替你决定的东西。

套餐卡不复用 `cards` 的标记：通用卡片最关键的"整卡可点"在这里是错的，套餐卡上
有按钮，整卡再套一层链接就是链接套链接。

## pricing-compare

套餐 × 特性的对比表。section 的键：

| 键 | 作用 |
| --- | --- |
| `plans` | 必需，纯文本数组，就是表头 |
| `items` | 必需，每行一项 |

每行：

| 键 | 作用 |
| --- | --- |
| `feature` | 必需，行标题 |
| `values` | 必需，长度必须等于 `plans` |

`values` 里 `true`/`false` 出勾与叉，其余按纯文本出（"4 小时"、"社区"）。

行的格数少于套餐数时这一行会被丢掉并 warn，不补空格：补上的话你看到的是"这个
特性某几档没有"，而真相是漏写了一格，两者在页面上长得一样。

布尔格里的图标各配一份仅供朗读的文本。图标是装饰，读屏软件会跳过 —— 少了那份
文本整张表在读屏软件那里是一片空白。

表格本体复用 `.matrix` 那一套：溢出时自己滚、表头与首列粘连、`scope` 正确、
打印时展开，全都已经在。

## code-plate

左边一段说明，右边一块代码。

| 键 | 作用 |
| --- | --- |
| `code` | 必需，代码本身 |
| `lang` | 语言标识，决定高亮 |
| `filename` | 代码块标题栏里的文件名 |
| `body` | 说明，渲染 Markdown |
| `actions` | 见下面 |
| `reverse` | 布尔，把代码放到左边 |

代码块是拼一段真围栏喂给渲染器，不是自己写 `<pre><code>` —— 高亮、复制按钮、
文件名标题栏、折叠、软换行全都跟着来，而且与正文里的代码块长得一样、行为也一样。

`lang` 与 `filename` 最终落在围栏的第一行，所以两者都限了形状：带引号或花括号的
`filename` 会提前闭合属性块，那时它被丢掉并 warn。

`reverse` 只在两栏时生效。塌成一栏之后恒是文字在上 —— 窄屏上先看到一块代码、
要往下滚才知道这一节在讲什么，那不是"视觉顺序"而是把内容藏起来。

## command-box

一条（或几条）安装命令，居中放大。

| 键 | 作用 |
| --- | --- |
| `commands` | 必需，字符串或数组 |
| `lang` | 默认 `shell` |
| `note` | 命令下面一句补充，渲染 Markdown |

`commands` 接受字符串或数组：单条命令是最常见的情形，为它写一个单元素数组是纯粹
的仪式。字符串里的换行会拆成多条。

与 `code-plate` 的区别是用途：那边是"说明配代码"的两栏，这边是"照这个敲"的一块，
没有说明栏，所以命令能放大居中。命令本身仍然左对齐 —— 终端里的命令是左对齐的，
居中会让多行命令读起来像诗。

## gallery

图片栅格，与 ```gallery 围栏同一份标记。

| 键 | 作用 |
| --- | --- |
| `src` | 必需 |
| `alt` | 必需 |
| `description` | 图下面的说明 |
| `href` | 点开去哪，通常是全尺寸原图 |

`alt` 必需且不接受省略：图集里的图承载信息（截图、示意图），一张没有替代文本的图
对读屏软件是完全不存在的。装饰性的图不该放进图集。

条目从 YAML 读而不是像围栏那样解析 Markdown 图片行 —— landing 的 section 全都是
结构化的键值，在这里插一套微语法会让你在同一个文件里切换两种写法。

## preview

一张大图，整幅展示。

| 键 | 作用 |
| --- | --- |
| `image` | 必需 |
| `image_alt` | 必需 |
| `caption` | 图下面的说明，渲染 Markdown |
| `frame` | 布尔，给图套一个窗口外框 |

与 `hero` 的图不同：hero 的图是标题旁边的陪衬，preview 的图**就是内容**。所以
`image_alt` 必需 —— 这一节除了那张图没有别的东西。

有 `caption` 时整块输出 `<figure>` + `<figcaption>`，说明与图的关联能被辅助技术
读出来；没有时就是一张图，不输出空的 figcaption。

## case-study

一个案例，图配叙述加几个数字。

| 键 | 作用 |
| --- | --- |
| `body` | 叙述，渲染 Markdown |
| `image` | 案例的图 |
| `image_alt` | 图的替代文本 |
| `metrics` | 一组 `{value, label}`，两者都必需 |
| `actions` | 见下面 |
| `reverse` | 布尔，把图放到左边 |

与 `code-plate` 同一条栅格定义，区别在右侧放什么。`reverse` 的行为也一样：只在
两栏时生效，塌成一栏后恒是文字在上。

案例里的数字用自己的类名而不是复用 `metrics` section 的：它们是补充证据，字号比
整节的 metrics 小一档。

## testimonials

引语加出处。

| 键 | 作用 |
| --- | --- |
| `quote` | 必需，渲染 Markdown |
| `name` | 必需，纯文本 |
| `role` | 身份/公司 |
| `avatar` | 头像 |

输出 `<figure>` + `<blockquote>` + `<figcaption>`。**出处不放进 `blockquote`。**
HTML 规范明确说了这一点：blockquote 里的内容是被引用的话，而"某某，某公司"不是那
句话的一部分 —— 放进去等于声称被引者说了自己的名字。

`name` 必需：没有出处的"引语"是一句无法核实的话，那不是引用而是文案。

## logo-wall

一排使用者或集成方的标识。

| 键 | 作用 |
| --- | --- |
| `src` | 必需 |
| `alt` | 必需，就是那个名字 |
| `href` | 点开去哪 |

`alt` 必需：这一节的全部信息就在那些名字里，少了替代文本的 logo 墙对读屏软件是
一片空白。

彩色 logo 并排会打架，所以默认降饱和度，悬停或聚焦时恢复。这不是隐藏信息 ——
alt 文本与形状都在，打印时也不降饱和度（单色打印机本来就会变灰）。

## capabilities

能力清单，每条带状态。

| 键 | 作用 |
| --- | --- |
| `title` | 必需 |
| `status` | `yes`（默认）、`partial`、`no` |
| `note` | 补充说明 |

与 `principles` 的区别是每条带状态而不是解释：principles 讲"我们为什么这样做"，
capabilities 讲"这个能力有没有、到什么程度"。

三档各配一份仅供朗读的文本 —— 图标是装饰，读屏软件会跳过它，少了那份文本读者只
听到能力名，听不出有没有。`no` 那档同时划掉标题：颜色差别在色觉障碍下不可靠。

## bar-chart

几个数值的横向条形对比。

| 键 | 作用 |
| --- | --- |
| `items` | 必需 |
| `max` | 基准值，缺省取最大值 |

每项：

| 键 | 作用 |
| --- | --- |
| `label` | 必需 |
| `value` | 必需，数字 |
| `display` | 条旁边显示的文本，缺省显示 `value` |

**零 JS。** 条长由内联的 `--td-bar` 给。走图表运行时要 434 KB（量过：333 共享块
+ 79 core + 22 bar），而这一节要画的是"谁大谁小"。真要坐标轴、图例、缩放、
tooltip 就用 ```echarts 围栏，那才是它存在的场合。

`value` 必须是数字。加了引号的 `"62"` 会被拒掉并 warn —— 这一节拿它算长度，而
字符串在算术上不通用。

`max` 缺省时最长的条铺满，读者比的是相对关系。要比绝对比例（几个都远小于 100 的
值）就显式给 `max`。

## markdown

一段自由 Markdown 当作一节。

| 键 | 作用 |
| --- | --- |
| `body` | 必需，渲染 Markdown |

出路给那些没有专门 section 的东西。写在这里而不是把内容挪到页面正文，是因为正文
只有一段且恒在所有 section 之后 —— 想在两个 section 之间插一段话，正文做不到。

**它不是万能 section。** 有专门 section 的东西用专门的：手搓一份卡片栅格得到的
是没有 `.td-card` 语义的一堆 div，样式改了不跟着变。

## contributors

头像墙。

| 键 | 作用 |
| --- | --- |
| `data` | 数据文件名，默认 `contributors` |

数据来自 `data/<key>.yaml`，与 `contributors` shortcode 同一份数据、同一份标记。
不联网 —— 主题不在构建时打 GitHub API：那会让离线构建失败，也会把限流问题带进每
一次 `hugo server`。

## download

分渠道的安装指引。

| 键 | 作用 |
| --- | --- |
| `data` | 必需，`data/download/<key>.yaml` 的文件名 |

整块与 `download` shortcode 同一份实现。版本号、仓库、tag 都是事实，只能来自数据
文件 —— 允许在 section 上写，同一页上就可能出现两个互相矛盾的版本号。

## cta

一段话加一组按钮，居中。结构上就是公共键加 `actions`，没有自己的字段 —— 但带
底色、居中、一组按钮是 landing 页收尾那一块的固定形态，让你用 `markdown`
section 手搓一遍等于把这个排版重复写进每个站点。

## actions

`hero`、`cta`、`code-plate`、`case-study` 与 `pricing` 的每个套餐都用它。每项：

| 键 | 作用 |
| --- | --- |
| `text` | 必需，纯文本 |
| `href` | 必需，过主题的 URL 策略 |
| `style` | `primary`、`secondary`（默认）、`text` |
| `icon` | 一个图标名 |

`text` 不渲染 Markdown：按钮上的文字是标签，而 `<em>` 一类标记在按钮里既没
意义又会打断读屏软件的连读。

外链自动带 `rel="noopener"`。不加 `noreferrer` —— 那会把正常的来源统计一起掐掉，
而要防的是被打开的页面通过 `window.opener` 改写来源页。

一节里最多一个 `primary` 是设计意图，但不强制：强制的代价是你写了两个时第二个
静默变样，比让它难看更难查。

## 打印

纸上不留满屏底色 —— 整块 `accent` 打印出来是一页实心油墨，而它承载的信息全在
文字里。各节改用边框区隔，按钮变成带下划线的链接。

`faq` 的答案全部摊开：纸上没有"展开"这个动作，而少了这条打印出来只有一串问题，
屏幕上还看不出来。

其余几处也按纸面调整：logo 不降饱和度（单色打印机本来就会变灰，再降一次就看不清
了），条形图的条换成描边加浅填充（实心色块费墨，而长度才是信息），预览图的窗口
外框收起（那三个圆点在纸上没有含义）。
