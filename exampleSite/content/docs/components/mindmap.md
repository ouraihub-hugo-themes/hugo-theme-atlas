`mindmap` 的 body 是一个 Markdown 嵌套列表，浏览器把它画成导图。可以点节点折叠、
拖拽平移、滚轮缩放。

{{< mindmap caption="主题的四个运行时与它们的取舍。" height="420" >}}
- 运行时
  - 图表
    - `mermaid` —— 浏览器端渲染，图种齐全
    - `goat` —— 构建时出 SVG，零运行时
    - `plantuml` —— 构建时出 URL，要服务器
  - 数据
    - `echarts` —— 八种图，按图种拆 chunk
  - 终端
    - `cast` —— asciicast，纯文本
  - 导图
    - `mindmap` —— 就是这一张
{{< /mindmap >}}

## 为什么是列表

思维导图的信息全在层级里，而嵌套列表把层级表达得一样清楚。这带来三件事：

1. 作者不用学第二套语法。
2. JS 没跑、chunk 没下下来、图画不出来时，页面上留下的是一份读得通的内容，
   而不是一段等着被渲染的源码。
3. 浏览器端只要 markmap 的绘图部分（77 KB），不要它那个 Markdown 解析器
   （656 KB）—— 列表由 Hugo 渲染成 `<ul><li>`，运行时从 DOM 走一遍就得到节点树。
   解析这件事 Hugo 和浏览器各自都已经做过了。

节点里的行内标记原样带过去：**粗体**、`行内代码`、[链接](https://gohugo.io/)
都在图上。

## 参数

| 参数 | 作用 |
| --- | --- |
| `caption` | 图注 |
| `num` `id` | 编号与锚点，登记进交叉引用表 |
| `height` | 画布高度，默认 400 |
| `expand` | 初始展开到第几层，默认全展开 |

`expand="2"` 只展开两层，读者点开其余的：

## 打印

打印时导图隐藏，列表出来：导图是可缩放可折叠的，纸上这两件事都做不到 ——
一张缩到看不清字的图不如一个完整展开的列表。
